Kỹ Thuật & Code

Những nguyên tắc giúp mã nguồn Node.js ổn định và dễ bảo trì hơn

Nguyễn Thành Luân 10 Tháng 01, 2025
7 phút đọc

Khi mới học Node.js, chỉ cần chương trình chạy đúng ở máy mình là thấy ổn. Nhưng khi đưa một ứng dụng hay Discord bot chạy liên tục nhiều tuần cho người khác dùng thật, phần khó hơn lại nằm ở sự ổn định, khả năng truy vết lỗi và việc sửa code cũ mà không làm gãy chỗ khác.

1. Tách cấu hình và không viết cứng thông tin nhạy cảm

Mọi chuỗi kết nối cơ sở dữ liệu, khóa API hay token của bot nên đọc từ biến môi trường thông qua file .env ngay từ lần khởi tạo dự án đầu tiên. Đi kèm luôn là file .env.example chỉ giữ tên biến để người khác (hoặc chính mình khi đổi máy) biết cần điền trường gì.

require('dotenv').config();

const config = {
    token: process.env.BOT_TOKEN,
    dbUri: process.env.MONGODB_URL,
    port: Number(process.env.PORT || 3000)
};

if (!config.token) {
    throw new Error('Thiếu biến môi trường BOT_TOKEN');
}

Kiểm tra sự tồn tại của các biến cấu hình bắt buộc ngay lúc khởi động giúp ứng dụng dừng sớm với thông báo rõ ràng, thay vì chạy nửa chừng mới phát sinh lỗi khó hiểu.

2. Bắt lỗi chủ động ở các hàm bất đồng bộ

Với fetch hoặc gọi API ngoài, một lỗi phổ biến là chỉ await mà không kiểm tra response.ok hoặc bọc try/catch. Khi dịch vụ bên thứ ba trả về lỗi 502 hay timeout, ứng dụng có thể dừng đột ngột nếu thiếu bước kiểm tra phản hồi.

async function fetchUserProfile(userId) {
    try {
        const response = await fetch(`/api/users/${userId}`);
        if (!response.ok) {
            throw new Error(`HTTP ${response.status} khi tải user ${userId}`);
        }
        const data = await response.json();
        return { ok: true, data };
    } catch (error) {
        console.error('[fetchUserProfile]', error.message);
        return { ok: false, error: error.message };
    }
}

3. Tận dụng Promise.all cho các tác vụ độc lập

Nếu cần lấy ba nguồn dữ liệu không phụ thuộc kết quả của nhau, đặt ba lệnh await nối tiếp sẽ cộng dồn toàn bộ thời gian chờ. Gom chúng vào Promise.all() (hoặc Promise.allSettled() nếu một nhánh lỗi không được phép làm hỏng phần còn lại) giúp giảm đáng kể thời gian phản hồi.

async function loadDashboardSummary(userId) {
    const [profile, orders, notifications] = await Promise.all([
        fetchProfile(userId),
        fetchRecentOrders(userId),
        fetchUnreadCount(userId)
    ]);

    return { profile, orders, notifications };
}

4. Tránh rò rỉ bộ nhớ từ Event Listener và kết nối

Ở các ứng dụng chạy dài ngày như bot Discord hay worker nền, lỗi bộ nhớ thường đến từ việc đăng ký listener lặp đi lặp lại trong hàm xử lý hoặc tạo kết nối database mới cho mỗi request. Nguyên tắc là khởi tạo pool kết nối một lần ở tầng bootstrap và luôn tháo listener khi đối tượng không còn dùng.

// Chỉ đăng ký listener một lần khi khởi tạo
const onMessage = (msg) => {
    if (msg.author.bot) return;
    // Xử lý thông điệp
};

client.on('messageCreate', onMessage);

// Khi đóng ứng dụng có kiểm soát
process.on('SIGTERM', () => {
    client.off('messageCreate', onMessage);
    client.destroy();
});

5. Tổ chức module theo trách nhiệm và ghi log vừa đủ

Thay vì dồn tất cả route, kiểm tra dữ liệu và truy vấn vào một tệp index.js, tách nhỏ theo cấu trúc routes/, controllers/, services/ giúp kiểm thử từng phần dễ hơn nhiều. Cùng với đó, các lỗi quan trọng nên ghi kèm ngữ cảnh (tên hàm, ID đối tượng, thông báo lỗi) hoặc dùng thư viện như winston để có thể lọc file error.log khi cần tra lại.

// routes/userRoutes.js
const express = require('express');
const router = express.Router();
const userController = require('../controllers/userController');

router.get('/', userController.getUsers);
router.post('/', userController.createUser);

module.exports = router;

6. Bảo vệ lớp đầu vào trước khi xử lý

Dù là API hay form tiếp nhận, luôn xác thực và chuẩn hóa dữ liệu từ người dùng (bằng express-validator, joi hoặc kiểm tra kiểu thủ công), đi kèm giới hạn tần suất (express-rate-limit) và header bảo mật (helmet) để giảm rủi ro khi mở cổng ra ngoài Internet.
